# 智能题库平台技术方案

本方案聚焦“智能题库”场景，说明题云平台如何通过 Spring Boot + Vue 前后端分离架构、RabbitMQ 事件流、Redis/Chroma 缓存与 LangChain4j AI 工具，提供题目沉淀、检索、组卷以及 RAG 助手协同创作等能力，帮助教学与出题团队高效管理题库资产。

## 1. 项目概述（背景/目标）
- **职责**：打造一体化的智能题库平台，支撑运营、教研、出题等角色完成题目沉淀、检索、组卷与问答。
- **设计要点**：采用分层架构隔离控制器、应用服务与基础设施；对题目、题集、试卷、附件、AI 向量等域对象进行端口化管理；保障权限隔离、异步一致性与扩展性。
- **关键技术点**：Spring Boot 3.5 + WebFlux、Sa-Token、RabbitMQ、MySQL + XBatis、Redis + Redisson、LangChain4j + DashScope/Chroma、Vue3 前端。
- **风险与对策**：题目与向量同步、模型调用成本、文件合规与权限隔离为主要风险，通过事务+事件驱动、缓存+限流、文件配额和鉴权策略降低影响。

### 1.1 背景与业务愿景
题云平台面向校内教研与培训机构，需沉淀大量题目/解析并可快速检索调用，同时借助 AI 助手提升出题效率、保障知识复用。当前以题库为核心，辅以 RAG 能力定位关联题目并辅助作答。

### 1.2 建设目标
- 建立统一的题目、题集、试卷生命周期管理。
- 让 AI 助手基于授权题库完成检索、问答与自动创题。
- 打通文件、缓存、消息与前端渠道，提供开放 API。
- 预留多租户、算力扩展与多终端交付能力。

## 2. 总体架构设计（架构风格/分层架构/关键链路）
- **职责**：描述服务拓扑、组件协作与数据流落点，为容量规划和扩展策略提供依据。
- **设计要点**：整洁架构 + 六边形端口/适配器；事件驱动补偿；流式 AI 响应；Redis 缓存承载会话与热点数据；Docker Compose 提供一键环境。
- **关键技术点**：Spring WebFlux、RabbitMQ Topic、LangChain4j AiService、Chroma 向量库、Redisson、Docker。
- **风险与对策**：跨组件网络依赖（Chroma/LLM）、消息积压、缓存穿透、单体扩展瓶颈，通过熔断重试、队列监控、缓存兜底与分层横向扩展策略控制。

### 2.1 架构风格
系统采用单体应用内的整洁架构：Controller 负责协议与参数校验，Application Service 聚合领域能力，Domain/Port 定义业务接口，Infrastructure Adapter 实现存储、消息、AI、文件、缓存、向量等适配；前端通过 REST/SSE，与后端保持解耦。

### 2.2 分层架构
- **Web 层**：`web/rest/v1`，包含用户、题目、题集、AI、公共文件等控制器，负责认证校验与 VO 映射。
- **Application 层**：`application/**` 提供 `QuestionAppService`、`QuestionCollectionService`、`AgentService` 等用例，依赖端口接口操作仓储/工具。
- **Domain/Port 层**：`application/**/port`、`dto`、`vo` 定义业务模型，与 ORM/AI/消息等解耦。
- **Infrastructure 层**：`infrastructure/**` 提供 `VectorAdapter`、`FileAdapter`、`AiChatAdapter`、`RedissonCacheService`、`QuestionTool` 等，对接数据库、Redis、LangChain4j、Chroma、RabbitMQ、本地文件系统。
- **Frontend**：Vue3 + Vite SPA，调用 `/api/v1` 与 `/api/v1/ai`，在终端消费 SSE。

### 2.3 端到端关键流程（题目上传→解析→向量化→检索→问答）
1. **上传/资产入库**：前端调用 `/api/v1/common/file`、`/api/v1/user/avatar` 上传文件，`LocalFileStorageService` 校验配额后写入本地磁盘并登记 `infra_file_metadata`。
2. **题目创建**：`QuestionController` 将 `CreateQuestionReq` 下发到 `QuestionAppServiceImpl`，校验题集归属与题型，生成题目/版本/统计记录并写入 `question`、`question_version`、`question_stats`、`collection_item`。
3. **事件发布**：事务提交后 `QuestionEventPublisher` 推送到 `question.topic`，载荷含 questionId、versionId、collectionId、ownerId。
4. **向量化**：`QuestionEventConsumer` 消费消息后调用 `QuestionVectorizeServiceImpl` 拼接题干+解析文本，查 `QuestionStat` 补充分难度等元数据，经 `VectorPort`/LangChain4j Upsert 至 Chroma（向量 ID=Q_{questionId}）。
5. **会话上下文**：前端向 `/api/v1/ai/collection/{id}/session` 申请对话，`AgentServiceImpl` 生成 memoryId 并在 Redis 保存 `ChatSessionContext`（userId、collectionIds、questionIds）。
6. **检索调用**：AI 会话中，LLM 工具 `QuestionTool.searchQuestion` 使用 memoryId 取上下文，构建 `SearchFilter`（ownerId、collectionId、difficulty/type），`SearchServiceImpl` 通过 `VectorPort.search` 在 Chroma 过滤命中题目。
7. **回答生成**：LangChain4j `CollectionAssistantAiService` 将命中题干、解析以及提示词注入模型（DashScope deepseek-v3.1），必要时调用 `QuestionTool.createQuestion` 自动生成题目。
8. **流式返回**：`AgentChatController` 将模型响应以 Reactor `Flux` SSE 输出给前端，前端逐 token 渲染，实现上传→解析→向量化→检索→问答闭环。

## 3. 技术栈选型（后端核心/数据存储/AI与智能化/安全与认证/基础设施与工具）
- **职责**：评估并固化核心技术组件，为后续演进提供依据。
- **设计要点**：所有依赖均在 `pom.xml` 显式声明，优先选用成熟生态；向量/模型能力通过 LangChain4j，缓存与异步任务走 Redis/Rabbit 组合。
- **关键技术点**：WebFlux、XBatis、Redisson、RabbitMQ、LangChain4j、DashScope、Chroma、SpringDoc、Actuator。
- **风险与对策**：模型或向量服务不可用、依赖冲突、版本升级风险，通过配置隔离、熔断、测试矩阵控制。

### 3.1 后端核心
Spring Boot 3.5 + WebFlux 负责 REST/SSE，`springdoc-openapi` 提供接口文档；XBatis/MyBatis + PageHelper（Pager）处理多表分页；Lombok、MapStruct（若有）减少样板代码。

### 3.2 数据存储
MySQL 保存业务数据；Redis (Redisson) 负责缓存、分布式锁与对话上下文；Chroma 自建为独立容器服务，通过 `VectorAdapter` 访问并随容器编排完成备份与扩缩容；`QuestionStat`、`paper/exam` 等表支撑后续统计。

### 3.3 AI 与智能化
LangChain4j `AiService` 绑定 DashScope deepseek-v3.1（chat）、streaming-chat-model 及 text-embedding-v4；`questionTool` 暴露 create/search/detail 能力；`RedisChatMemoryStore` 维护对话记忆。RAG 过滤条件由 `SearchFilter` 构建。

### 3.4 安全与认证
Sa-Token 统一管理登录态、会话续期与多端并发策略；`CommonResultCodeEnum` 定义错误码；`ApplicationException` 贯穿全局。文件上传白名单、配额和 AccessLevel 限制保障资产安全。

### 3.5 基础设施与工具
RabbitMQ（Topic Exchange + JSON MessageConverter）处理领域事件；Actuator 暴露健康检查；Docker Compose、Dockerfile(frontend/backend) 提供容器化。测试栈包含 `spring-boot-starter-test`、Mockito、MyBatis Test。

## 4. 核心功能模块设计
- **职责**：细化关键子域的业务规则与实现策略。
- **设计要点**：应用服务 + 端口适配器模式，确保每个模块可独立演化。
- **关键技术点**：Sa-Token 权限校验、RabbitMQ 事件补偿、LangChain4j 工具、Redis 会话、文件配额、向量过滤。
- **风险与对策**：权限绕过、异步延迟、上下文丢失、模型幻觉，通过鉴权、重试、缓存 TTL、提示词约束与审计日志管理。

### 4.1 用户与权限
- **职责**：注册、登录、退出、头像、基础信息、默认题集创建。
- **设计要点**：`UserController` 借助 `UserAccountService`、`Sa-Token` 完成注册与登录；`UserEventPublisher` 在注册后推送消息创建默认题集；头像存储走文件服务。
- **关键技术点**：密码加密（spring-security-crypto + Hutool）、Sa-Token 登录状态、`CacheControl` 控制头像缓存。
- **风险与对策**：暴力破解、头像越权访问、注册风控，通过失败次数计数、URL 授权、RabbitMQ 消费幂等化控制。

### 4.2 资源管理 / RAG 能力
- **职责**：题目 CRUD、题集管理、附件上传、题目向量化、检索 API。
- **设计要点**：`QuestionAppService` 管理题目与版本；`QuestionCollectionService` 负责题集创建/更新/删除；`QuestionVectorizeService` 在 MQ 事件后 Upsert 向量；`SearchService` 提供过滤参数。
- **关键技术点**：XBatis 分页、RabbitMQ Topic 事件、LangChain4j Embedding & Filter、`QuestionTool` 工具暴露。
- **风险与对策**：异步延迟导致检索不到最新题目，通过 MQ ack + 死信监控、向量 Upsert 幂等；RAG 幻觉通过提示词 `CollectionAssistantPrompts` 限制。

### 4.3 知识库隔离 / 空间
- **职责**：以 `question_collection` 为知识空间，绑定 `owner_id`，`collection_item` 管理题目顺序。
- **设计要点**：用户登录后可创建多个题集，默认题集来自注册事件；题目/检索/AI 调用均携带 collectionId 进行隔离；`QuestionCollectionService` 做 owner 校验。
- **关键技术点**：`CollectionPresenceCheckerPort` 检查默认题集、`QuestionInCollectionPageQuery` 负责分页筛选。
- **风险与对策**：误删题集、共享越权，通过软校验（owner 不符返回 NOT_FOUND）、引用计数（集内题目删除检查）。

### 4.4 多租户
- **职责**：明确组织/租户之间的数据隔离与账号模型。
- **设计要点**：平台当前按用户维度（`owner_id + collectionId`）隔离数据，不引入 tenant 概念；如需多租户，可在现有 schema 中扩展 `tenant_id` 并同步写入向量 metadata。
- **关键技术点**：Sa-Token 登录上下文、数据库 owner_id 字段、向量 metadata 的 ownerId。
- **风险与对策**：未来租户化需求应提前评估 schema 变更窗口；在准备扩租户时需要迁移现有向量元数据以保持 RAG 过滤准确。

### 4.5 异步任务
- **职责**：跨域事件（用户注册、题目 CRUD）触发默认题集、向量同步等后台任务。
- **设计要点**：RabbitMQ Topic + JSON converter；发布端在事务提交后发送；消费端通过幂等逻辑（检查默认题集、构造向量 ID）保证重复安全。
- **关键技术点**：`RabbitTemplate`、`SimpleRabbitListenerContainerFactory`、`QuestionVectorizeServiceImpl`。
- **风险与对策**：队列积压、消费者失败，通过预取、死信告警、幂等处理及重放脚本保障。

### 4.6 检索与问答链路
- **职责**：结合检索增强生成与工具调用，为用户提供题目搜索、问答、创题功能。
- **设计要点**：`AgentServiceImpl` 基于 Redis 记忆，在聊天中调用 `questionTool` 的 search/detail/create 能力；`CollectionAssistantAiService` 通过提示词限制回答范围；Flux SSE 输出。
- **关键技术点**：LangChain4j AiService、DashScope 深度模型、`QuestionToolDocs`/`ParamDocs` 约束入参、`AssistantChatReq` 记录 memoryId/message。
- **风险与对策**：模型幻觉/越权输出，通过系统提示词明确“不可泄露 ID”，同时在工具调用中再次校验 owner/collection；Flux backpressure 防止客户端断流。

## 5. 数据库设计概览（按领域列出核心表与职责）
- **用户域**：`user`（账号、加密密码、锁定字段）、`infra_file_metadata`（文件路径、所有者、AccessLevel、配额查询）。
- **题目域**：`question`（题目主数据）、`question_version`（题目版本/题干/解析/答案）、`question_stats`（难度、正确率、曝光因子）、`collection_item`（题集与题目版本关联顺序）、`question_collection`（题集元信息）。
- **评测域**：`paper`、`paper_item`、`exam`、`exam_item_snapshot`、`exam_question_stat` 支撑组卷与考试统计（后续可扩展）。
- **文件域**：`infra_file_metadata` 记录文件大小/路径/访问级别，供题目附件与头像共享。

- **职责**：关系型数据承担强一致性业务；文件/向量/缓存负责补充静态资源与检索能力。
- **设计要点**：ID 使用雪花算法；业务表无外键（由服务保证一致性）；统计表保持写少读多特性。
- **关键技术点**：`HutoolSnowflakeIdGenerator`、`Pager` 分页、JSON 列存储题目选项与附件。
- **风险与对策**：缺乏 FK 可能导致孤儿数据，通过应用层事务与后台巡检脚本清理；`question_stats` 数据延迟需异步任务补偿。

## 6. API 设计规范（RESTful/统一响应/鉴权/错误码）
- **职责**：确保前后端及第三方集成遵循统一协议、错误码与鉴权方式。
- **设计要点**：HTTP 动词匹配 CRUD；路径语义化 `/api/v1/{domain}`；支持 SSE（`MediaType.TEXT_EVENT_STREAM_VALUE`）；响应统一为 `ResultVO`，分页使用 `PageResult`；错误码来自 `CommonResultCodeEnum` 与领域异常枚举。
- **关键技术点**：Spring Validation (`@Valid`)、SpringDoc 文档、Sa-Token（header/cookie token）、全局异常处理（抛出 `ApplicationException`）。
- **风险与对策**：SSE 与普通 HTTP 并存需前端正确处理 Content-Type；错误码未覆盖的异常需回退到 500000 并打日志；鉴权遗漏通过 Controller 切面/拦截器审计。

## 7. 部署与运维（容器化/配置/CI-CD/监控/日志）
- **职责**：描述交付、环境、监控与告警方案，确保平台可运维。
- **设计要点**：Docker Compose 为本地/PoC 环境（MySQL、Redis、RabbitMQ、backend、frontend、Chroma、文件卷）；暂不建设 CI/CD 与集中式监控，采用本地/手工构建发布；配置通过 `application-*.yml` + 环境变量（.env example）注入敏感信息；Actuator 与标准输出日志提供基础观测。
- **关键技术点**：Dockerfile 多阶段构建（前后端）、Spring Profile、`CacheControl` 头提升 CDN 命中率、Actuator health/info/metrics、集中式日志（Logback -> stdout，交由容器收集）。
- **风险与对策**：本地文件存储在多实例下需共享存储或 Object Storage；Rabbit/Chroma 外部依赖需健康检查；缺少 CI/CD 需制定手工发布清单和回滚脚本；Actuator 端点需加权限或网关隔离；如无集中监控，需在日志中保留关键审计与故障信息。

## 8. 总结
- **职责**：回顾方案价值并展望演进路径。
- **设计要点**：坚持端口/适配器、事件驱动、RAG 中台化三条主线；围绕题目资产、检索、AI、文件、安全构建统一平台；向量库由自建 Chroma 承载，数据按用户维度隔离。
- **关键技术点**：LangChain4j + Chroma 的 RAG 能力、RabbitMQ 事件链、Sa-Token 安全框架、Redisson 缓存、Docker Compose 交付。
- **风险与对策**：短期以手工发布与基础日志监控支撑，需要严格遵循发布 checklist；如未来引入多租户或集中式运维能力，当前 schema 和架构已预留扩展点（tenant_id、CI/CD、APM），可按路线图迭代。
